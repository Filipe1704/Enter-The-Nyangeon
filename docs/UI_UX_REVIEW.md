# UI/UX Review / 界面体验检查

> 检查日期：2026-10-10。
> 检查方式：场景与交互源码静态检查，辅以数值和条件表达式复核。
> 证据状态：运行中的 `Enter The Nyangeon (DEBUG)` 窗口截图两次超时，未获得有效截图；本文不构成实机视觉审查。
> 优先级：P1＝影响核心操作、取消操作或决策信息；P2＝影响理解、效率或可访问性。优先级是本次检查建议，不代表用户已敲定。
> 后续修复：同日完成首批代码修复、真实场景回归与局部渲染检查，见 §6；§1–5 保留初次检查记录，行号对应修复前源码。

## 1. Scope & flow / 范围与流程

目标是让玩家能理解入口、完成选角和难度选择、调整设置，并在战斗与升级中读懂状态、可靠地操作。

| 步骤 | 界面 | 源码检查结果 |
|---|---|---|
| 1 | 主菜单 | 键盘确认链路缺失；触屏需要两次点按，与部分后续控件不同。 |
| 2 | 角色选择 | 存在预览、语音和确认反馈；触屏两次点按规则需要明确提示。 |
| 3 | 难度、模式、支援选择 | 难度决策信息不足；返回没有取消已经启动的入场计时器。 |
| 4 | 设置与操作说明 | 设置分组明确；滚动提示、键盘访问、移动端不可用状态需要改善。 |
| 5 | 战斗 HUD 与暂停 | 有血量数值、延迟血条和退出确认；HUD 震动未受画面震动设置控制。 |
| 6 | 回合升级与局内装备 | 有收益/负面信息、重抽费用与余额校验；字号下限和装备收益预览存在问题。 |
| 7 | 主菜单商店 | 有购买确认、余额不足反馈和已购状态；其触屏行为与升级等控件应统一说明。 |
| 8 | 结算、记分板与筛选 | 结算统计和记录输入入口齐全；筛选列表触屏拖动判定存在方向性错误。 |

上述状态来自源码，不代表已走通这些步骤。截图、点击手感、动画遮挡及焦点的实际表现均待实机验证。

## 2. Strengths / 可以保留的设计

- **战斗信息有多种表达。** 血量同时提供数值、即时血条与延迟血条，临时血量另有 `+数值`；适合快速感知损血。证据：`ui/game_ui.gd:70`。
- **重要消费和退出已有保护。** 主菜单角色购买有确认流程与余额校验；暂停退出有 Yes/No；重抽会在金币不足时阻止消费。证据：`ui/character_shop_card.gd:117,183`、`ui/pause_screen.gd:291,316`、`ui/UpgradeScreen.gd:201`。
- **已有降低视觉干扰的基础。** 画面震动、伤害数字、特效、闪白可分别配置；设置变更会保存。后续可以在这些能力上补齐统一的减少动态效果策略。证据：`script/game_option.gd:105,222,244,266`。
- **本地化和文字适配有复用基础。** 已有翻译键、`auto_text.gd` 和 `wrap_fallback_below`，适合把个别页面的手写缩字逻辑收敛到一致规则。证据：`script/auto_text.gd:3,10,78`。

## 3. Findings / 问题与建议

### 01. P1 — 主菜单和设置没有完整的键盘确认链路

- **证据：** 主菜单按钮实例使用 `ui/menu_button.tscn:103` 的可聚焦 `PanelContainer`，但 `script/menu_button.gd:29` 只处理触屏和 `shoot`；`project.godot:141` 的 `shoot` 绑定鼠标/手柄，没有键盘确认键。设置页签同样只处理触屏和 `shoot`（`script/option_button.gd:22`），开关为自定义 `PanelContainer`（`ui/game_option.tscn:394`）。`scenes/main/menu_button_joypad.gd:17` 的确认只打印文本，且没有发现场景引用该脚本，不能视作现有补救。
- **体验影响：** 即使键盘焦点能移动，Enter/Space 也不能通过当前自定义处理器执行主菜单动作；设置等页面缺少一致的焦点与确认规则。手柄的 A 同时绑定 `shoot`，不能据此断言所有手柄操作失效。
- **建议：** 统一接受 `ui_accept`；进入页面时设置初始焦点，为聚焦状态提供与悬停同等清晰的反馈，并在关闭弹层后恢复焦点。可保留像素外观，复用原生 `Button` 的输入语义。
- **验收：** 从主菜单开始，只用键盘完成选角、难度、设置和返回；再独立验证手柄完整流程，确认动作不依赖鼠标位置。

### 02. P1 — 返回难度页不能取消已经安排的入场

- **证据：** 难度选定后启动 0.5 秒计时器（`ui/level_button.gd:79,94`、`ui/level_button.tscn:284`），超时直接切换战斗场景（`ui/level_button.gd:96`）。返回仅发送 `level_select_out` 并播放 `RESET`（`ui/level_select.gd:27`），两份脚本均没有停止计时器或在超时回调中检查是否已取消。
- **体验影响：** 玩家选择难度后立即返回，界面虽然收起，已安排的入场仍会执行；这破坏了“返回即撤销当前选择”的预期。
- **建议：** 返回时停止所有待启动计时器、复位选择状态；超时回调再次检查本次选择是否有效。更明确的流程是先选择难度，再用“开始战斗”确认。
- **验收：** 选难度后 0.5 秒内返回，等待超过启动时间仍停留菜单；再次进入能正常选择。

### 03. P1 — 记分板筛选把向上拖动当作点击

- **证据：** `ui/menu_box_button.gd:84` 在触摸释放时用 `offset <= 10` 判断点击，没有取绝对值，也不检查横向位移、手指索引及取消状态。组件被记分板的排序、角色和模式筛选复用（`ui/menu_box.tscn:8`、`ui/menu_box_character.tscn:9`、`ui/menu_box_gamemode.tscn:10`）。
- **体验影响：** 向上拖动 80 个局部坐标单位时 `-80 <= 10` 成立，会进入选择逻辑；向下同样距离则不会。滚动筛选时可能意外改变筛选项。
- **建议：** 采用二维移动距离阈值并跟踪单一手指；拖动或取消后禁止点击，只有同一手指在有效目标内释放才执行选择。
- **验收：** 上下左右拖动均不改变筛选；短点按选择一次；双指操作不串状态。表达式复核已确认方向不对称，实际事件传递仍需真机验证。

### 04. P1 — 装备预览可能把实际收益显示为 0%

- **证据：** `ui/ability_shop_item_card.gd:217` 在第三属性负值分支先 `int(value)` 再乘 100；书包的减伤条目确实包含 `-0.05`（`resources/equip/bag.tres:28`）。按该表达式会显示 `0%`，而值应表达为 `-5%`。累计属性的负值分支却先乘 100（`ui/ability_shop_item_card.gd:285`），两个展示口径不一致。
- **体验影响：** 玩家可能认为本次升级没有减伤收益，影响消费与构筑决策，也会怀疑升级是否生效。
- **建议：** 统一属性格式化入口，集中处理百分比、正负号和精度；预览展示“当前 → 升级后”，并区分承伤率降低与数值增加。
- **验收：** 书包跨入含 `-0.05` 的升级条目时显示 `-5%`；预览、累计属性与实际数值变化一致。本次已用资源原值复核算式，未操作游戏消费。

### 05. P2 — 单次与两次触摸的规则不一致

- **证据：** 主菜单、角色卡、升级卡第一次触摸预览、第二次触摸执行（`script/menu_button.gd:31`、`ui/player_card.gd:200`、`ui/ability_upgrade_card.gd:92`）；设置页签和开关则按下即执行（`script/option_button.gd:24`、`script/game_option.gd:105`）。升级页重抽、下一回合同样在触摸按下时执行（`ui/UpgradeScreen.gd:193,216`）。升级卡的提示仍是固定的 `| CLICK |`（`ui/ability_upgrade_card.tscn:460`）。
- **体验影响：** 玩家难以预测“一次点击会预览还是执行”，容易多按或漏按；桌面操作提示也没有解释触屏两阶段语义。
- **建议：** 普通导航和开关统一单次操作；需要阅读的卡片用明确的“查看详情 → 选择”按钮，或明确提示“再次点按确认”。滚动列表的提交尽量放在释放并排除拖动之后。
- **验收：** 新玩家能从提示预测下一次触摸结果；多次快速点按不重复提交。

### 06. P2 — 文字适配以极小字号换取容纳空间

- **证据：** 升级卡每帧调用 `_auto_text()`，标题或卡片超限时继续缩字，直到字号 1（`ui/ability_upgrade_card.gd:33,61`）；正文初始字号为 10，父容器开启裁剪（`ui/ability_upgrade_card.tscn:562,602`）。设置标签允许缩到 7（`ui/game_option.tscn:392`）。
- **体验影响：** 长译文或 Mod 描述可能“没有溢出但无法阅读”；升级卡的缩字过程还可能在显示期间改变布局。实际触发频率、最终像素大小需实机确认，不能仅凭字号数值判定所有文本都不可读。
- **建议：** 先定可读字号下限，再用换行、摘要和独立详情区容纳长内容；使用已有事件驱动适配，避免持续缩小。优先保住效果数值和负面条件的可读性。
- **验收：** 用四种语言和长 Mod 文案检查卡片，正文不低于约定下限，重要效果不裁剪，页面稳定后字号不继续变化。

### 07. P2 — 难度缺少可比较的决策信息

- **证据：** `ui/level_button.gd:29` 只填充名称和颜色，按钮文本只有 `LEVEL` 与难度名（`ui/level_button.tscn:251,268`）。资源却定义了显著不同的生命、伤害、分数与奖励参数：NORMAL 生命/伤害参数为 0.8/0.8，INSANE 为 5.0/2.5（`resources/level/normal.tres:12`、`resources/level/insane.tres:12`）。
- **体验影响：** 玩家能看出难度分级，却无法估计挑战差异与收益，更难判断首次游玩该选哪档。
- **建议：** 补中文难度说明、推荐对象与主要差异；展示参数时先核对实际计算口径，再用玩家可理解的描述或相对倍率呈现。选择后汇总角色、难度、模式与支援，再开始战斗。
- **验收：** 玩家不查外部说明也能比较相邻难度；不要把配置参数直接误称为最终敌人属性。

### 08. P2 — 设置的可滚动性与音量结果不够明确

- **证据：** 设置使用隐藏滚动条的 `ScrollContainer`，内容最小高度为 360，视区顶部还有 20 偏移（`ui/game_option.tscn:320,332,336`）。四个音量行只有标签和滑条，没有当前值标签（`ui/game_option.tscn:781` 至文件末尾）；`ui/volume_slider.gd:18` 调整后直接保存。
- **体验影响：** 玩家可能没发现下方设置；调整音量后难以准确复现数值或辨认是否归零。真实裁剪位置与滚动提示是否足够仍需截图确认。
- **建议：** 溢出时显示细滚动条或底部渐隐提示；音量显示百分比，提供静音状态及恢复默认入口。设置即时保存的行为可以保留。
- **验收：** 第一次进入便能发现下方内容；拖动、键盘修改及重新打开页面后，显示数值都与保存值一致。

### 09. P2 — 移动端不可用设置仍保留可操作外观

- **证据：** 全屏和垂直同步在移动端触摸后仅提示“该选项在移动端无效”，分辨率由透明 STOP 层拦截（`script/game_option.gd:32,59,141`、`ETN_localization.csv:113`）。开关根交互区为 18×18 设计单位（`ui/game_option.tscn:396,523,584`），标签没有转发点击给开关。
- **体验影响：** 玩家需要点过才知道不能修改；小交互区在手机上也有误触风险。18×18 是设计坐标，不能直接换算成某设备物理像素或据此判定标准不合格。
- **建议：** 移动端隐藏纯桌面设置，或使用禁用样式和常驻说明；让整行标签与开关共同形成点击区域，并按真实屏幕缩放验证触控大小。
- **验收：** 不可用状态无需试点即可识别；手机上用拇指稳定操作相邻设置，不依赖精确点中图标。

### 10. P2 — 关闭画面震动仍不能稳定 HUD

- **证据：** 相机震动检查 `Game.shake_screen`（`scenes/game_camera/gamecamera.gd:71`），但 HUD 的 `hurt_anim()` 无条件对生命数值和贴图执行多段随机位移，并设置血条闪白（`ui/game_ui.gd:112`）。该函数没有读取画面震动或闪白频率设置。
- **体验影响：** 对动态效果敏感的玩家关闭画面震动后，仍可能看到 HUD 晃动；受击时最需要读数的区域也在移动。这里确认的是控制范围缺口，不是对闪烁安全阈值的判定。
- **建议：** 增加统一的“减少动态效果”策略，覆盖相机、HUD、卡片倾斜与装饰动画；保留静态边框、血条差值等受击反馈，降低动态效果时仍能感知危险。
- **验收：** 关闭相关效果后，连续受击时生命读数位置稳定；仍能明确识别伤害与低血量。

## 4. Recommended order / 建议处理顺序

1. **先修可靠性和决策信息：** 取消入场计时器、拖动误选、百分比预览错误，补齐键盘确认链路。
2. **再统一交互规则：** 触屏预览/确认、按下与释放时机、焦点恢复、不可用状态与整行点击区域。
3. **再改善阅读与选择：** 字号下限、详情区、难度比较、滚动提示和音量数值。
4. **最后补实机视觉检查：** 信息层级、对齐间距、装饰与文字争夺注意力、背景对比度、弹层遮挡及减少动态效果。

## 5. Initial evidence limits / 初次检查的证据边界与补测

- 没有有效实机截图，不能判断整体美观、实际文字清晰度、真实对比度、动画完成态或遮挡；没有完成端到端交互验证。
- 没有进行屏幕阅读器、手柄全流程、Android 真机、触摸事件路由或不同宽高比的测试；不声称符合任何完整可访问性标准。
- 本次直接复核了书包 `-0.05` 在现有预览表达式中变为 `0%`，以及筛选条件对 `-80` 和 `80` 位移的不同结果。该复核仅验证源码算式。
- 后续至少覆盖：1280×720、1920×1080、手机常见宽屏；四种语言；长 Mod 文案；鼠标、纯键盘、手柄与触屏。
- 联机覆盖层、Mod 专属页面、测试房调试菜单未展开检查，应作为后续独立范围。
- 本次只新增检查记录并维护知识库；没有修改游戏功能或本地化文件，没有执行游戏内购买、退出或存档操作。
